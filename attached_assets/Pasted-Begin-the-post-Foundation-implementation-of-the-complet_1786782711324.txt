- lifecycle status
- registration date
- timestamps

Approved lifecycle states:

- draft
- active
- inactive
- withdrawn
- graduated
- deceased

Do not use national ID as StudentProfile primary key.

Initial student-specific fields may include:

- Create draft StudentProfile from an existing Person
- Create Person and StudentProfile atomically
- Activate student
- Change lifecycle status
- Search students using authorized scope
- View masked/basic profile
- View restricted fields when authorized
- Correct student-specific data with reason/history

No automatic person merging by name.

5. GAZA CIVIL-REGISTRY INTEGRATION
==================================================

Implement a restricted advisory civil-registry integration.

Expected source fields include:

- national ID
- full name
- gender
- area
- city
- street
- father ID
- mother ID
- birth date
- marital status
- deceased indicator
- religion
- birth country
- representative ID
- relationship

Inspect any existing database/table/import files before choosing final names.

Support a configurable source such as `gaza_civil_records` or the actual existing table name. Do not create two competing registry tables.

Requirements:

- Registry records are read-only through the application.
- Use indexed normalized national-ID lookup.
- Support approximately 1.5 million records.
- Never load the complete registry into application memory.
- Import/load in chunks or stream rows.
- Do not commit the real registry dump to Git.
- Do not expose registry search broadly.
- Record authorized lookup purpose, actor, and outcome without logging the raw ID.
- Registry lookup is advisory.
- Registry mismatch produces a review warning.
- Registry data never silently overwrites an existing Person.
- `is_dead` or another sensitive registry value must never automatically change a GCV Person lifecycle.

Create:

- CivilRegistryRecord model/read repository
- CivilRegistryLookup service
- CivilRegistryImport command
- CivilRegistryMatch DTO
- CivilRegistryAutofillProposal
- Accept/reject-field selection
- Safe lookup audit integration

Student registration workflow:

1. Secretary enters national ID.
2. Backend authorizes the lookup.
3. Identifier is normalized.
4. Existing GCV Person/Student is checked first.
5. Registry is checked.
6. Proposed values are displayed.
7. Secretary reviews individual fields.
8. Accepted fields create/update the draft Person.
9. StudentProfile is created explicitly.
10. Source and decisions are audited.

Do not automatically create parents/guardians from father_id or mother_id. Present them as possible follow-up lookups.

7. ENROLMENT AND PLACEMENT
==================================================

Implement StudentEnrollment.

It belongs to:

- StudentProfile
- InstitutionSemester
- ClassGroup

Institution, semester, academic level, and period must be derived through relationships rather than duplicated as trusted request data.

Statuses:

- draft
- active
- completed
- promoted
- repeating
- transferred
- withdrawn
- suspended
- graduated

Rules:

- A student cannot have conflicting active educational-institution enrolments for overlapping dates.
- A student cannot have two active placements in the same InstitutionSemester.
- ClassGroup must belong to the selected InstitutionSemester.
- InstitutionSemester must be open before activation.
- Draft placement may be prepared for a future semester.
- Closed/archived history remains readable.
- Historical enrolments are never repointed to a new class.
- Capacity violations require explicit approved override and reason; ordinary users cannot silently exceed capacity.
- Central read access does not grant enrolment mutation.
- Secretary mutations require matching institution, semester, period, position, and permission.

Provide:

- Create draft enrolment
- Change draft placement
- Activate enrolment
- Complete enrolment
- Withdraw/suspend
- Transfer student
- Create promotion proposal
- Review promotion proposal
- Apply approved proposal atomically
- List complete enrolment/placement history
- Resolve current placement

Transfer:

- Closes the prior active enrolment appropriately.
- Creates a new draft/active target enrolment according to approved workflow.
- Requires reason and actor.
- Is atomic.
- Never overwrites history.

Promotion:

- Produces proposals, never automatic official placement.
- Supports promoted, repeating, graduated, transferred, and unresolved decisions.
- Requires review before activation.

8. STAGED EXCEL PATCH IMPORTS
==================================================

Implement `.xlsx` and `.csv` student imports.

Inspect currently installed packages before adding a spreadsheet dependency. If a new package is needed, verify compatibility with the locked Laravel/PHP versions and document the decision.

Workflow:

1. Upload
2. Store source metadata securely
3. Parse in chunks
4. Map columns
5. Normalize
6. Validate
7. Detect existing records
8. Show preview
9. Approve
10. Apply through domain actions
11. Produce result/error report

Never write uploaded rows directly into official tables.

Entities:

- ImportBatch
- ImportFile
- ImportRow
- ImportColumnMapping
- ImportRowResult
- ImportAppliedRecord

Batch statuses:

- uploaded
- parsing
- ready_for_mapping
- validating
- ready_for_review
- applying
- completed
- completed_with_errors
- failed
- cancelled

Patch behavior:

- Existing unchanged student → skip
- Existing record with safe missing fields → propose patch
- Conflicting official value → conflict requiring review
- New valid student → propose creation
- Duplicate row in file → reject/flag
- Invalid reference → reject/flag
- Ambiguous identity → never auto-merge
- Unknown class/semester/period → reject/flag
- Unauthorized institution row → reject without applying
- One failing row must not corrupt successful recoverable batches

Required row-level result statuses:

- created
- updated
- skipped_existing
- conflict
- invalid
- unauthorized
- failed

Support column aliases in Arabic and English.

Large files must use queues/chunking and bounded memory.

Record:

- Actor
- Portal
- Institution/semester scope
- Original filename
- File hash
- Import time
- Source row number
- Applied entity references
- Safe changes
- Errors
- Result summary

Never include raw national IDs in ordinary logs or downloadable error URLs.

Provide downloadable Excel/CSV result reports with masked sensitive values.
